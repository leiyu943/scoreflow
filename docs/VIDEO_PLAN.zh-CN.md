# 谱音 ScoreFlow 视频介绍方案

[返回 README](../README.md) · [发布步骤](GITHUB_RELEASE.md)

建议录一支 **4 分半左右的完整演示**，再剪出 **60 秒短版**。主线围绕一个真实需求：三页吉他谱，一次导入，识别后连成完整 MIDI，点谱就能听，并能把文件带到音乐软件里。

开头先让观众看到和听到结果，安装细节放在后半段和视频简介。软件当前为 0.2.0 预览版，宣传重点是“多页连接、谱面定位播放、MIDI 导出”；五线谱专项优化是技术特点，六线谱继续优化需要同时说清。

## 先准备一个能讲清楚的演示曲目

- 准备**同一首曲子的三张清晰五线谱图片**，命名为 `page-1.png`、`page-2.png`、`page-3.png`。优先使用自己写的小曲，或已确认可以公开展示的谱面版本。
- 选择旋律容易听出、节奏不过于复杂的片段；最好有一处换页、一个跨页延音和一处明显休止，能展示连接后的实际效果。
- 提前完整跑一遍，确认三页识别、落点、自动翻页、换音色和导出都能正常演示。发现错误就选一个可说明的例子，不用把错误藏成“完美识别”。
- 另备一张六线谱或混合谱，用十秒左右展示模式入口与“优化中”状态，不必把它作为主演示曲目。
- 把导出的 MIDI 在自己使用的音乐软件中打开一次，确认能展示音符；录制时保留这个验证环节。

程序自带的“晨间小调”可以用于展示界面、音色和点击播放。它是内置播放示例，**不能把载入示例剪辑成模型刚识别成功的画面**。真正的识别演示应使用导入图片后的实际任务。

## 4 分半分镜

| 时间 | 画面与动作 | 观众要得到的信息 |
| --- | --- | --- |
| 0:00–0:15 | 成品画面，点击第三页某个音符，留两秒听声音，再展示整曲卷帘 | 点谱就能定位，三页是一首曲子 |
| 0:15–0:40 | 软件全景，出现名称“谱音 ScoreFlow” | 本地桌面工具，解决什么问题 |
| 0:40–1:10 | 多选三页，检查页序，演示一次前移/后移 | 不必一页页手点识别 |
| 1:10–1:35 | 选择自动/五线谱模式，开始识别，展示逐页进度 | 每页实际识别，再合成整曲 |
| 1:35–2:20 | 查看卷帘，从第一页末尾播放到第二页；选择第三页后点击音符 | 连续播放、自动翻页、整曲定位 |
| 2:20–2:50 | 同一片段用古典吉他与钢琴各听一次；略调速度 | 有采样音色，能换音色和调速 |
| 2:50–3:25 | 导出 MIDI，给文件命名，在音乐软件中打开并播放 | 文件确实能保存、能继续使用 |
| 3:25–4:00 | 展示五线谱“已优化”、六线谱“优化中”，打开模式下拉 | 当前重点、支持范围与实际边界 |
| 4:00–4:30 | README、安装要求与 GitHub Release 页面 | 到哪里下载，适合什么设备，如何反馈 |

识别等待时间可剪短或加速，画面标注“等待已缩短”或实际倍速。不要将加速后的长度当作识别耗时。若展示耗时，写明本次页数、设备和实际用时。

## 可直接照读的口播

### 0:00 开场

“如果一首吉他谱有三页，我希望一次把它们读完，最后拿到的是一首完整的 MIDI。像这样，我点第三页的这个位置，它就从整首曲子对应的位置开始播放。”

此处停两秒，让观众听见声音，再继续。

### 0:15 介绍软件

“我把原来标注工具里的识别部分，拆成了一个独立的桌面软件，叫谱音 ScoreFlow。它可以把谱面图片转成 MIDI，也可以看着谱面来试听。界面用的是 Electron，Python 放在后台做识别。完整运行环境准备好以后，识别和音色处理都在本地进行。”

### 0:40 导入多页

“这里我一次选中同一首曲子的三页。程序会按文件名里的数字排序，我也可以在上面调整顺序，或者继续追加谱页。顺序确认好以后，只要开始一次识别，它就会一页一页地处理，最后再把各页连起来。”

### 1:10 展示识别

“现在可以看到每一页的进度。已经完成的页会保留下来，如果中途取消，后面再继续，可以复用完成的结果。追加新页时，也只需要识别新加的部分。”

此处如果加速，保留进度变化并添加加速标识，不必持续口播。

### 1:35 完整曲目与点击播放

“识别完成以后，下面显示的是整首曲子的音符。这里连的是各页实际的时间，页尾的休止也会保留下来。现在从第一页快结束的地方播放，走到下一页时，它会自动翻页，声音继续。

“如果我只想听后面某一段，可以直接选第三页，再点这个音符。它定位到的是整首曲子的时间。卷帘和进度条也都能用来定位。”

### 2:20 音色与速度

“底部现在有七种采样音色，默认是古典吉他。我把同一段切换成钢琴，再听一下。MIDI 保存的是音高、时值等演奏事件，所以可以换音色。试听速度也可以调整，调速时保持原来的音高。”

每种音色留两到三秒，不要用口播盖住对比。

### 2:50 保存与外部使用

“识别成功以后，完整 MIDI 会自动保存。我也可以从这里另存一份，导出的 MIDI 会带上选择的音色。现在把这个文件放进音乐软件，可以看到刚才整首曲子的音符，还能继续编辑或编曲。结构兼容的时候，也可以导出 MusicXML。”

### 3:25 优化重点与边界

“这次我重点做的是五线谱，在原有识别链路上加了专项调整和校正。六线谱和混合谱也有入口，其中六线谱还在继续优化，建议试听核对。混合页在自动模式下优先读取五线谱；如果想读里面的六线谱，可以手动选择六线谱模式。

“当前版本处理的是谱面图片，还没有 PDF 导入和音符编辑器。识别需要 Windows x64 和 NVIDIA 显卡。我这次是在 RTX 3070 8GB 上验证的。”

### 4:00 下载与结尾

“源码、安装指引和当前版本说明会放在 GitHub，链接在简介。本次按源码目录发布，先安装 Node.js、Python 3.12 和 NVIDIA 驱动，再运行“安装识别环境”，完成后双击“启动谱音”。模型、音色和数 GB 的推理依赖会从上游下载到独立目录，不放进源码。六线谱默认使用 Tabbox 的公开模型。

“欢迎大家试用，也欢迎提供可以公开分享的谱面样本和具体错误位置。我会继续改进五线谱和六线谱识别。”

录到这一段时，应当已经创建真实仓库；按 README 展示两个启动入口和实际安装步骤，不要把源码下载本身说成已经包含全部运行环境。

## 录屏与收音要点

- 尽量录应用窗口，谱面放大到能清楚看到音符；不要只录整块桌面后让 UI 缩成小字。
- 系统音频与麦克风分别录制。口播时降低软件音量，试听时停口播，让人听清实际声音。
- 主演示始终用同一首三页曲目；换音色对比使用相同片段和接近音量。
- 录制文件选择器前，准备一个只放演示素材的文件夹，避免展示无关私人文件或路径。
- 成片应包含“选三页 → 实际识别 → 点击第三页 → 自动翻页 → 导出 → 外部打开”的完整证据链。
- 想强调“比直接调用原模型更准”时，另做同一输入、同样条件的前后对比，说明具体改正了什么；没有这组对比就使用“做了专项调整和校正”的表述。
